  no separate spoken feedback; Repeat speaks the question only

Improvements
1. Realistic questions: interviewer prompt (QUESTION_SYS) enforces ONE question, 1-2 sentences, ~8-25 words,
   conversational, practical, no bundled sub-questions, no textbook preambles, no answer hints.
2. Profile match: role, company, level, job description (pasted or from the selected job) and resume are in context.
3. Interview structure: per-type stage plan (intro -> resume/projects -> core technical -> problem solving ->
   scenario -> behavioral/HR). Stage is a suggestion; the interviewer may follow up instead.
4. Conversational: each question carries a short "reaction" to the previous answer ("Correct.", "Not quite.").
   Weak/incomplete answers get one short probing follow-up; max one follow-up in a row, then it moves on.
5. Difficulty control: Easy/Medium/Hard. Fresher/Junior start Easy and only rise after strong answers;
   Mid/Senior start Medium. Two weak answers lower difficulty.
6. Voice: only the reaction + current question are spoken, cleaned of markdown/labels; listening starts after speech ends.
7. Separate evaluation: EVAL_SYS rubric (correctness, relevance, completeness, clarity, 0-10 each) with an explicit
   rule not to penalise short but correct answers; final report prompt has the same rule.
8. Validation: every generated question is checked (word limit 30, or 38 for scenario/problem; max one "?";
   max 2 sentences; no "also/additionally/and how would you" bundling; no near-duplicate of earlier questions).
   Rejected drafts are regenerated once with the reasons; if still invalid the first question sentence is kept.

[2026-10-09] Fix: OA / learning resources / AI interview stuck loading
-----------------------------------------------------------------------
Cause: user's Gemini API key exhausted its free-tier quota (HTTP 429 on every Gemini model) and the last fallback model was
overloaded (503, responses taking 60s+), so every AI request retried through all models twice and the UI kept loading.
Fix (backend/ai.py + backend/.env):
- Automatic fallback to the Emergent universal key (EMERGENT_LLM_KEY, models in EMERGENT_FALLBACK_MODELS) when the own key fails.
- Quota-exhausted models are skipped for 30 min, overloaded/timed-out ones for 2 min, so later requests go straight to a working model.
- Every AI call has a hard timeout (AI_CALL_TIMEOUT_SEC=75) so nothing hangs forever.
- Update: Emergent key fallback removed at user's request. backend/.env GEMINI_API_KEYS holds 4 Gemini keys (comma separated);
  ai.py tries the best model on every key before falling back to the next model; a key+model that hits its quota is skipped for 30 min.
